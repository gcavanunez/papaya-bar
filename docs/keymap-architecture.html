Papaya Bar · Tab Manager · architecture note

One keydown listener.
The whole vim layer.

The tab manager's keyboard UX — sequences like dd and gg, counts like 3j, visual mode, which-key hints, the ? cheat sheet and the statusline — all hangs off a single declarative binding table dispatched by one window-level keydown listener. No hotkey library. Zero new dependencies.

// 01

The single
source of truth

Every shortcut is a plain object in TabManager.vue — keys, modes, description, group, and a run() closure over the component's own actions. Because the table is data, everything that needs to know about shortcuts reads the same array. Add one entry and it shows up in the help overlay, the which-key popup, and the dispatcher simultaneously. Nothing can drift.

consumes it → dispatch

useKeymap.ts matches incoming key tokens against binding.keys and fires run({ count }).

consumes it → which-key

Pending prefix (m…) filters the table for completions: w new window, g new group.

consumes it → help overlay

KeymapHelpOverlay.vue groups visible bindings by group and renders the ? cheat sheet.

reflects it → statusline

TabManagerStatusline.vue shows mode, pending keys (3d), cursor 12/148, selection count.

// 03

Life of a
keystroke

Guards first, grammar second. The engine refuses to fight menus, dialogs, text fields or focused buttons — then parses count → sequence → resolution.

dead-end swallow — a key that breaks a pending sequence is consumed, vim-style, not leaked to the page.

chord timer — exact match with longer candidates (none today, by design) waits 450 ms, then falls back.

repeat gate — held keys only auto-fire bindings marked repeat: true (navigation). A held d can never machine-gun dd.

// 04

Modes are
derived, never
stored

There is no mode ref to desync. Mode is a computed over two facts that already exist: is the search input focused? and is a visual anchor set? Focus the input by any means — click, /, autofocus — and you are in SEARCH. Blur and you are out. Impossible states are unrepresentable.

const keymapMode = computed<KeymapMode>(() => { if (isInputFocused.value) return 'search' if (visualAnchor.value !== null) return 'visual' return 'normal' })

NORMAL

Full grammar live: motions, counts, operators, Esc is progressive — selection → search filter.

VISUAL

Anchor + cursor define a range. d closes it, y copies it, both exit the mode.

SEARCH

Letters type into the filter; only explicit search-mode bindings (Ctrl-j, Enter, Esc) intercept.

// 05

Anatomy of
a binding

targetTabs(count) encodes the vim philosophy in one function: an explicit selection always wins; otherwise the operator acts on count rows from the cursor. So dd closes one tab, 3dd closes three, and with tabs selected the same keys close the selection.

Destructive actions are wrapped in an undo toast backed by chrome.sessions.restore() — press u or click Undo. Fearless dd is the point.

// TabManager.vue — one entry from the table { id: 'action-close', keys: 'd d', // space-separated sequence → dd modes: ['normal'], // visual mode binds bare 'd' instead group: 'Actions', // section in the ? overlay description: 'Close tab / selection', run: ({ count }) => closeTargets(count), // 3dd → count = 3 }, // selection-aware targeting — the whole trick const targetTabs = (count = 1): Tab[] => { if (tabsSelected.value.size > 0) return selectedGroup.value return flatTabs.value.slice(cursorIndex.value, cursorIndex.value + count) } // hookup — the component hands the engine two getters, done const { pendingDisplay, whichKey } = useKeymap({ mode: () => keymapMode.value, bindings: () => bindings, })

cursor, not focus

cursorIndex points into flatTabs (the grouped list, flattened in display order). The ring renders in both views — list rows and grid cards (TabRow :is-cursor) — independent of DOM focus. Watchers clamp it when tabs close and reset it when the filter or category changes.

virtualized rows

List view renders ~20 absolutely-positioned rows via useWindowVirtualizer (scrollMargin = list's document offset). j/k at 300 tabs costs the same as at 30.

scroll math

scrollCursorIntoView() reads the virtualizer's measurements and scrolls the window manually so the cursor row clears the sticky header (~330px) on the way up and the statusline on the way down.
